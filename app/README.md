# androidWTF — Android app

A GUI over the `wtf` engine. It contains **no install logic of its own**: it
renders a selection and asks the engine to act on it over Termux's
`RUN_COMMAND` intent, so the app and the CLI cannot disagree about what a
selection actually does.

> **Status: unbuilt.** The source is complete and statically checked, but it has
> never been compiled — there was no Android SDK on the machine it was written
> on. Expect to fix compile errors on first build.

## How it talks to the engine

```
com.termux/com.termux.app.RunCommandService
action  com.termux.RUN_COMMAND
path    /data/data/com.termux/files/home/.wtf/repo/platforms/android/bootstrap/wtf
args    ["install", "--tools", "nmap,ffuf,..."]
```

Three prerequisites, each failing differently:

| | Detectable? | Handling |
|---|---|---|
| Termux installed | yes, via `<queries>` | Home screen offers the F-Droid link |
| `RUN_COMMAND` permission granted | yes | Home screen offers the grant button |
| `allow-external-apps=true` | **no** | Stated up front as a prerequisite — there is no API for it, and without it commands silently do nothing |

That third one is the awkward one and the reason the UI explains it rather than
waiting for the user to discover silence.

## Why the catalogue is bundled

`app/src/main/assets/catalogue.json` is generated by `wtf catalogue --json` and
committed. Browsing, filtering and pack-building therefore work before Termux
is installed, before it is configured, and with no network. The engine is only
needed to actually install something.

Regenerate after changing the catalogue:

```bash
python3 platforms/android/bootstrap/wtf.py catalogue --json > app/src/main/assets/catalogue.json
```

## Design

It deliberately does **not** look like a terminal. The site is
terminal-adjacent because it sits next to a CLI; the app is a normal mobile app
that happens to share the palette — Android green on a green-shifted near-black,
with the T0–T3 tier colours carried over as the one consistent signal.

## Known gaps

- **Device tier is not read back.** `RUN_COMMAND` returns results via a
  `PendingIntent`, which the MVP does not register, so the app cannot yet show
  the tier or per-step progress. Everything above tier is shown unmarked until
  that lands. This is the first thing to build next.
- Packs open as `--dry-run` rather than installing, so a mis-tap cannot install
  170 tools.
- No APK-provider handling yet: `play`, `nethunter` and first-party tools are
  listed but not actionable. Obtainium handoff is not wired up.
